# v0.7.0: Product Definition

Released 2026-08-16.

v0.7.0 adds Free-compatible `hubspot_product` management through HubSpot's
`2026-03` Products API without changing any v0.6.0 state contract.

The resource requires name, SKU, description, and an exact decimal-string
price. Optional cost and positive whole-month recurrence distinguish null
(unmanaged) from empty string (clear). HubSpot decimal normalization is a
semantic no-op, and PATCH sends only changed managed properties.

HubSpot's generated numeric Product ID is the only state and import identity.
The provider never searches or recovers by SKU or name. An ambiguous create can
recover only when HubSpot returned an ID that passes an exact read-back. Without
one it fails with exact-ID import guidance.

Destroy archives the exact ID and verifies both active absence and the same
archived identity. Already absent or archived objects complete idempotently.
External archival removes state and declared configuration creates a new ID.
Archived Product retention is HubSpot-managed and the provider has no restore
operation.

The exact scopes are `crm.objects.products.read` and
`crm.objects.products.write`. Legacy `e-commerce` is neither used nor required.
The release remains deliberately limited to standard Products. Tiered pricing,
folders, status, tax, terms, URLs, custom properties, line items, associations,
and search adoption remain deferred.

The stable-keyed `product-definition` demo module and cumulative Northstar
journey exercise plan, apply, exact verification, decimal normalization, drift
repair, refresh archival, import, replacement, and teardown under the current
OpenTofu and Terraform versions. Publication additionally requires a guarded
runtime property-schema check and disposable live Product probe that proves
root-folder omission, recurrence, SKU uniqueness, archive reads, duplicate
archive behavior, and cleanup.

The cumulative journey also routes ancestor File folder renames with direct
child folders through HubSpot's asynchronous hierarchy update. The protected
cumulative journey verifies the terminal task's exact-ID folder result, rejects
older folder snapshots by revision, and proves the exact descendant path before
moving a staged file home. It also preserves observed membership names on
local-only removal-guard changes and accepts a missing CRM user projection at
teardown only after exact membership and aggregate projection absence are both
proved.

Terraform Registry and OpenTofu Registry ingest the same signed immutable
GitHub release. Registry ingestion remains asynchronous and is recorded
separately from successful GitHub publication.
