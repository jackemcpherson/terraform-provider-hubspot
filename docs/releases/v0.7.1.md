# v0.7.1: Security Patch

Released 2026-10-29.

v0.7.1 rebuilds the v0.7.0 provider with patched Go and HTTP/2 dependencies.
It adds no configuration surface and changes no state contract.

Provider binaries now build with Go 1.26.10 instead of Go 1.26.6 and with
`golang.org/x/net` v0.62.0 instead of v0.58.0. `govulncheck` found these
findings reachable from the v0.7.0 provider binary:

| Package | Findings | Fixed in |
| --- | --- | --- |
| `net/http` | GO-2026-6603, GO-2026-6605, GO-2026-6610, GO-2026-6611, GO-2026-6612, GO-2026-6613, GO-2026-6617 | Go 1.26.9 |
| `crypto/tls` | GO-2026-6607 | Go 1.26.9 |
| `net/textproto` | GO-2026-6608 | Go 1.26.9 |
| `crypto/x509` | GO-2026-6809 | Go 1.26.10 |

The provider reaches `golang.org/x/net/http2` through gRPC and
`terraform-plugin-go`, so the `golang.org/x/net` side of GO-2026-6603,
GO-2026-6611, GO-2026-6612, and GO-2026-6617 also applies. gRPC moves from
v1.82.1 to v1.83.2, which includes the fixes for GO-2026-6348, GO-2026-6441,
and GO-2026-6443.

The module language version is now 1.26.0 because every patched
`golang.org/x/net` release declares it. Building from source therefore needs
Go 1.26. Registry users install prebuilt binaries and need no change.

The release also includes one File folder fix. HubSpot can return a stale
terminal task payload after it applies an asynchronous folder update. The
provider now accepts that update only after an exact-ID read-back proves the
planned state, instead of failing on the stale task payload.

Terraform Registry and OpenTofu Registry ingest the same signed immutable
GitHub release. Registry ingestion remains asynchronous and is recorded
separately from successful GitHub publication.
