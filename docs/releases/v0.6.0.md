# v0.6.0: CRM User Profile

v0.6.0 adds `hubspot_crm_user_profile` without changing the account-membership
contract or existing v0.5.0 state. The new resource manages selected CRM user
profile properties for an existing Settings account membership.

The resource stores the account-specific CRM user ID and joins it to the
configured Settings user ID through `hs_internal_user_id`. Create follows every
CRM collection cursor and polls the join 20 times at one-second intervals.
Missing and duplicate joins produce different diagnostics. The timeout explains
that human activation or CRM materialization can be required.

Job title, availability, timezone, and working hours are optional managed
properties. Null values remain unmanaged. The resource requires one managed
property, accepts the documented availability and day values, includes minute
1440, rejects invalid ordering and expanded-day overlap, and serializes working
hours canonically.

Updates verify both identity domains and PATCH only changed managed properties.
A changed timezone is verified before working hours. Semantic no-ops send no
PATCH. Import accepts the CRM ID or `membership:<Settings-ID>` and stores the
canonical CRM ID.

Destroy performs no remote write. It stops management and leaves the selected
profile values in HubSpot. The release does not add membership, roles, teams,
seats, permission sets, invitations, names, email, activation, or global
identity deletion to this surface.

The exact scope pair is `crm.objects.users.read` and
`crm.objects.users.write`. The stable-keyed `crm-user-profile` demo module
depends on the account-membership output and exercises plan, apply, verify,
drift repair, refresh, adoption, and non-destructive teardown under current
OpenTofu and Terraform versions. Maintenance no longer presents a static scope
family string as runtime scope verification.

Terraform Registry and OpenTofu Registry ingest the same signed immutable
GitHub release. Registry ingestion remains asynchronous and outside the
publication gate.
