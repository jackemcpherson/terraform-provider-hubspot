# v0.4.0 — Files configuration

v0.4.0 adds the additive Files configuration surface for HubSpot Free. It
preserves every v0.1.x state upgrade, the complete v0.2.0 CRM property-schema
contract, and the v0.3.0 Form definition contract.

`hubspot_file_folder` manages one explicit File Manager folder and
`hubspot_file` manages one locally sourced Managed file. Both resources use
generated folder and file IDs as their only identity and import only those
non-zero decimal IDs. Names, paths, URLs, hashes, sizes, and timestamps are
mutable or computed observations, never adoption keys.

The exact `files` scope is required. Managed file content is supplied through a
sensitive local `source_path` and a reviewed lowercase SHA-256 digest. Content
bytes never enter provider state, diagnostics, or release evidence. The release
supports `PRIVATE`, `PUBLIC_INDEXABLE`, and `PUBLIC_NOT_INDEXABLE` access;
enforces the Free 20,000,000-byte per-file boundary; and rejects documented
executable extensions before mutation.

Files updates preserve generated identity. Folder rename uses PATCH; folder
move waits for the asynchronous task, and both read back the exact ID. File
metadata changes use PATCH; byte replacement uses PUT and verifies the preserved
file ID and creation time. When changing both a file and ancestor folder names,
apply the file change first, then rename folders root-to-leaf. HubSpot file
updates can restore an older ancestor-folder snapshot, and overlapping folder
renames can be applied from stale hierarchy snapshots.
Delete verifies active absence, refuses non-empty folders, and documents
HubSpot-managed Trash retention without claiming purge.

The stable-keyed `files-configuration` module composes one hierarchy level at a
time through generated parent IDs. Cumulative and released journeys retain prior
CRM property schema and Form definition surfaces, prove both OpenTofu and
Terraform source identities, and require file-first, leaf-first cleanup.

This release does not manage CMS Developer File System content, runtime delivery,
URL imports or overwrite, signed URLs, hidden access states, implicit paths,
folder cascade deletion, GDPR purge, or arbitrary file API options.

Both Terraform Registry and OpenTofu Registry publish the same signed archive
set. Publication is immutable; post-publication observation and both-engine
journeys remain separate release-completion gates.
