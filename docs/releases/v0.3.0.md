# v0.3.0 — Form definition configuration

v0.3.0 adds one deliberately narrow `hubspot_form_definition` resource for an
active HubSpot Free contact email Form definition. The additive release preserves
the complete v0.2.0 CRM property-schema surface and all v0.1.6 state upgrades.

The resource uses the generated Form UUID as its only canonical identity. It
supports exact-ID import, typed email-field and presentation reconciliation,
supported drift repair, and terminal archive verification. The new stable-keyed
`form-definition` module provides safe defaults and returns generated IDs by key.

The token needs the exact `forms` scope in addition to whichever CRM property
scopes the same configuration manages. Forms-only acceptance continues to use a
separate least-privilege credential from the union-scoped cumulative Northstar
journey.

This release does not manage form submissions or responses, consent models,
notification recipients, automation, arbitrary field/group structures,
non-email fields, restore, or permanent deletion. Destroy archives the Form and
verifies its exact retained Archived identity; it does not claim purge.

Both Terraform Registry and OpenTofu Registry publish the same signed archive
set. Post-publication completion requires one live Form identity to survive
state migration from Terraform's provider source to OpenTofu's source and back
before one final verified archive.
