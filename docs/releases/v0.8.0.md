# v0.8.0: Contact Segment Definition

Released 2026-10-29.

v0.8.0 adds Free-compatible `hubspot_contact_segment` management through
HubSpot's Lists `2026-03` API without changing any v0.7.0 state contract.

The resource supports manual, dynamic, and snapshot definitions. Dynamic and
snapshot filters use unordered OR groups containing unordered AND predicates.
The supported predicate contract is one text or select equality value, or a
property-presence test. It excludes Contact records and memberships, numeric,
Boolean, datetime, event, association, historical, substring, and multi-value
filters.

The generated positive-decimal ILS list ID is the only state and import
identity. The provider never searches or recovers by name. Name updates remain
in place. Dynamic filter updates remain in place, while snapshot filter changes
replace the resource.

The provider polls exact ID and current `listVersion` after asynchronous
writes, rejects unsupported remote meaning, and accepts an ambiguous write only
after complete exact-ID read-back. A create without a returned ID stops with
exact-ID import guidance.

Deleted definitions remain readable as HubSpot-managed tombstones for up to 90
days. Refresh retains a supported tombstone in state, and the next apply
restores the same ID. Active and tombstoned imports are supported. Permanent
absence removes state. Destroy verifies the same tombstoned identity and never
purges it.

The exact scopes are `crm.lists.read` and `crm.lists.write`. The provider does
not read Contact property schema or Contact records. HubSpot remains
authoritative for property-kind mismatches, name conflicts, and account
capability.

The stable-keyed `contact-segment-definition` demo module manages all three
variants. The cumulative Northstar lifecycle and dual-engine behavioral suite
exercise no-op planning, rename, dynamic drift repair, snapshot replacement,
active import, tombstoned import and restore, purge, destroy, and terminal
cleanup.

To upgrade, change the provider version constraint to `0.8.0` and run
`tofu init -upgrade` or `terraform init -upgrade`. Existing state needs no
migration. Grant `crm.lists.read` and `crm.lists.write` only to tokens that
manage Contact segment definitions.

Deal pipeline configuration is the next slice, as v0.9.0. Association
definitions are deferred, not scheduled, under ADR 0005 because they cannot
pass the Free-only delivery contract. No association-label code, permissions,
workflow, demo, or documentation enters this release.

Terraform Registry and OpenTofu Registry ingest the same signed immutable
GitHub release. Registry ingestion remains asynchronous and is recorded
separately from successful GitHub publication.
