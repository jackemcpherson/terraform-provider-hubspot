# v0.5.0: Account Membership

v0.5.0 adds guarded HubSpot account-membership configuration while preserving
the v0.1.x state boundary and every CRM schema, Form definition, and Files
resource contract. Existing configurations need no migration.

`hubspot_account_membership` creates and reads membership through the
`/settings/users/2026-03` API. It stores the canonical numeric Settings user ID,
which is distinct from CRM user and owner IDs. Import accepts that ID or an
explicit `email:` lookup and always writes the canonical ID. Duplicate create
never silently adopts an existing membership.

Email and the explicit welcome-email choice are creation-only and
replacement-triggering. Imports record welcome delivery as false because the
historic choice is unknowable. Optional names are also computed observations;
configured updates require an activated user and fail closed whenever a current
role or team assignment exists. `USER_NOT_ON_ANY_HUBS` is terminal rather than
indefinitely retried.

Removal defaults off. When explicitly enabled, destroy rereads the exact ID and
email, refuses a Super Admin, deletes account membership, and verifies absence
through ID, email, and collection reads. It does not delete the global HubSpot
identity. State removal remains the non-destructive alternative.

Tokens need Settings users read/write scopes or HubSpot's documented CRM users
read/write alternative. The release deliberately excludes roles, teams, seats,
permissions, activation state, CRM profile fields, deactivation, and
global-identity deletion.

The stable-keyed `account-membership` demo module requires an explicit welcome
choice, exposes canonical IDs, and keeps deletion guarded. Weekly maintenance
continues the cumulative Northstar journey under current OpenTofu and Terraform
versions without sending a welcome email.

Terraform Registry and OpenTofu Registry ingest the same signed immutable
GitHub release. Registry ingestion remains asynchronous and outside the
publication gate.
